# Zhaosheng

精神卫生学院应用心理招生宣传网站。

参考 Core-A Updates 的深色编辑式构图，使用原生 HTML/CSS/JavaScript 实现环形导航与画面滚动联动。后台通过 Worker、D1 与 R2 保存内容及图片。

## 本地预览

运行 `npm run preview`，前台为 http://127.0.0.1:4175/，后台为 http://127.0.0.1:4175/admin，两者均可在 Codex 内打开。后台支持图片上传、图文、字号和位置编辑；保存后已打开的前台自动更新。首次启动导入已迁移的九个自定义篇章及原图，后续启动保留本地修改。

Windows 日常使用可双击本目录的 `启动本地预览.cmd`（或运行 `npm run preview:start`）。它会先检查本地服务：已经运行则直接复用；尚未运行则在后台启动，关闭启动窗口后仍可使用。电脑重启或服务退出后，再双击一次即可。启动器不安装开机任务、不发布网站，也不会重置图文和音乐；若端口被其他程序占用，会提示错误并保留该程序。

此工作区只监听本机地址。后台保存到被 Git 忽略的 `.local-preview/`（数据库及图片），不会改写线上网站或 `src/published-content.json`。该目录是本地编辑数据，请保留或备份；服务器退出、电脑重启后，重新运行 `npm run preview` 即可继续管理。`local-workspace.mjs` 和 `preview-pages.mjs` 仅用于本地，Cloudflare 构建不会使用本地管理员身份。

在此目录运行 `npm install`、`node build.mjs`、`node server.mjs`，打开 http://127.0.0.1:4173/admin 。本地预览使用独立的虚构管理员账号和 `.local-data` 数据，不影响线上内容。需要 Node.js 24。

## 内容替换

- `/admin`：编辑九个篇章的图片、目录、标题、正文、说明及网站设置，点击“保存并更新”后持久保存并供前台读取。新增“师资团队”和“实践成长”均可自行改名。主标题可留空，前台和即时预览会隐藏空标题。
- `public/`：前台及后台的界面源码，`src/default-content.json` 提供数据库首次使用时的默认内容。
- `src/worker.mjs`：服务端鉴权、原子版本更新和图片上传。拒绝未授权账号和跨站写入请求。
- 管理员配置不随公开源码提交。可通过 `ADMIN_EMAILS` 构建环境变量或本地 `src/admin-allowlist.json` 配置，格式参考 `src/admin-allowlist.example.json`。未配置管理员时，线上写入权限默认关闭。服务器通过 Sites 平台提供的登录身份校验写入权限。
- `db/schema.ts` 与 `drizzle/`：数据库结构及生成的迁移。不得修改已部署的迁移。
- `src/default-content.json` 中的学校名称、文案和照片均为展示示例。

后台内容持久化在 D1，图片存储在 R2。上传支持 JPEG、PNG、WebP，单张最大 8 MB。保存采用内容版本校验，旧窗口会显示冲突提示，不覆盖新版本。已打开的前台重新获得焦点或刷新时读取最新内容。

各篇章在“文字大小”中分别设置主标题（24–80 px）和正文（12–28 px），默认为 60 / 16 px。字号以桌面为基准，手机端和后台预览适当缩放。旧数据读取时补齐默认值，不改写数据库；旧编辑窗口缺失字号字段时保留当前已保存字号。

“文字位置”分别调整标题和正文的左右、上下偏移（-50% 到 50%，0 为自动排版）。文字位置限制在画面内；超出可用高度的长正文可滚动阅读。图片上方短句已从前台、后台和后续保存数据中移除。旧编辑窗口缺少位置字段时保留已保存的位置。

九模块版本读取旧五模块或七模块数据时，只补上缺失的新模块，保留已有标题、图片、取景及网站设置；下一次后台保存会持久保存九模块内容。旧编辑窗口提交五模块或七模块草稿时，也会保留后来模块的数据，并继续校验保存版本，防止覆盖新版本。此更新不需要数据库结构迁移。

构建：`node build.mjs`；服务端验证：`node --test cms.test.mjs`。本地存储适配仅用于开发测试；线上不会使用测试身份或本地文件系统。

循环导航验证：`node --test journey.test.mjs`。原生页面滚动使用循环缓冲并自动回到中间区域，9→1 与 1→9 均为一格；点击目录按环形最短路径切换。标题与正文共享 `public/text-layout.js`，使后台预览与前台使用同一位置约束。

## 交互

鼠标滚轮、触摸滑动与浏览器原生滚动驱动左侧目录旋转和右侧画面揭示；点击目录或上一篇/下一篇按钮可平滑滚动。目录支持方向键、Home/End。尊重系统减少动态效果设置。

轮盘中心的双层环线、刻度光点、进度弧与章节数字跟随滚动位置联动，不再使用校徽图片。动画只在滚动或切换章节时更新；减少动态效果模式下关闭环线转动。

画面停在两个篇章的交替位置时，点击图片空白处或“查看完整画面”按钮，会沿最短方向对齐最近的完整篇章。手机滑动、正文滚动和文字选择不会触发画面对齐。

后台新增“背景音乐”栏目，支持 MP3 上传（最大 20 MB）、曲名修改和启用开关，点击“保存并更新”后全站使用同一首音乐。预设为用户提供的《Dusk · Peter Jeremias》。前台打开时通过原生 autoplay 和 play() 尝试有声自动播放，默认播放器音量 10%，播放完毕自动重播；浏览器拦截时，首次真实点击、鼠标按下、触摸结束、触屏/笔抬起或按下 Enter/空格后再次启动，音频就绪及重新进入页面时也会重试。首次访问的浏览器可能必须要求用户交互，网页代码无法保证所有设备零操作自动出声。iOS 忽略原生音量设置时，使用 Web Audio 的 GainNode 将音乐输出降至 10%（最终响度仍受系统音量影响）。前台保留播放/暂停及原生进度控制，移除了播放器底部说明文字，播放状态仅供辅助阅读设备播报；手动暂停后保持暂停，切换篇章、回到页面或修改音乐名称不会重置播放进度。后台试听仍由管理员手动播放。

音乐设置单独保存到 D1 的 `site_content` 表（记录 id 为 `music`），不会改动九个篇章。上传音乐存储到 R2，通过 `/audio/` 提供带字节范围的播放和拖动进度响应。旧数据库不需要新增表；管理员认证及保存版本校验沿用现有机制。

本地后台保存音乐后，会同步生成 `public/music.json` 和所选 `public/audio/` 文件，供以后部署携带。构建同时检查本地已保存的 BGM，输出包含曲名、启用状态和原始 MP3 字节。Cloudflare Pages 尚未接入数据库时，仍可播放随部署携带的预设音乐；线上后台更换音乐需要部署说明中的 D1、R2、Access 配置。前台不再提供文件选择功能。

## 部署与数据迁移

此仓库包含前台、后台界面、Sites Worker 服务端源码及 Cloudflare Pages 适配。Cloudflare Pages 使用 `npm run build` 和输出目录 `dist`，具体配置见 [Cloudflare 部署说明](DEPLOY-CLOUDFLARE.md)。原平台使用 `npm run build:sites`。直接发布仓库根目录不会生成可访问的首页。

Pages 版本使用 Cloudflare Access 验证管理员身份，存储仍为 D1 / R2。当前已将原站保存的九个自定义篇章导入 `src/published-content.json`，九张原始上传图片位于 `public/media/`，校验值见 `src/published-media.json`。未配置数据库时展示这份完整内容快照，图片可直接从静态资源读取；未配置管理员认证时关闭后台写入。Netlify 或普通服务器仍需要适配其登录、内容接口和图片存储。

`server.mjs` 是仅供本机使用的开发预览，它提供虚构测试身份，不能作为公开服务器运行。管理员邮箱、生成的部署包和本地数据均不提交到 GitHub。

后台保存的图文独立于 Git 源码。迁移时应另外导出当前内容记录和 /media 图片，并恢复到新数据库和图片存储。默认内容只用于首次运行，不能替代当前线上图文。
